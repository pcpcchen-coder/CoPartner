# CoPartner

*[繁體中文](README.md) · English*

> An **ambient AI assistant** for macOS. It watches what you do, has a local model
> write your activity into a human-readable "action script", and — when you press a
> hotkey — hands that script to a cloud model that picks up your unfinished work
> without you having to explain anything.

**Primary target:** Mac mini M4 / Apple Silicon, macOS 26 Tahoe.

---

## The three ideas

1. **Watch cheaply — Smart Capture Engine.** No fixed-rate full-screen screenshots.
   Foveated + dirty-region capture instead: high resolution and frequency around the
   cursor and focused window, low everywhere else, and only *changed* tiles get looked
   at closely. Borrowed from KVM-over-IP / VNC incremental updates and from how the
   human fovea works.

2. **Remember legibly — Action Script Narrator.** A local model (Apple
   FoundationModels ~3B, or Qwen via MLX) continuously turns raw events into a readable
   script: L0 event log → L1 narrated steps → L2 rolling summaries.

3. **Hand off fast — Cloud Takeover.** On hotkey, the script (a textual causal history)
   plus a small focused screenshot goes to Claude Computer Use, which continues the
   open loop. You never re-explain context.

Sensitive data and high-frequency observation stay local; complex reasoning and action
planning go to the cloud, with an explicit privacy gate in between (PII redaction, app
blocklist, PIPL cross-border rules).

### What "in progress" means right now

The executor is being built in slices so that *the ability to actually run commands*
lands as its own reviewable change:

| Slice | State |
|---|---|
| XPC skeleton — separate process, structured argv, no execution capability | ✅ verified |
| Caller code-signing verification, both directions | ✅ verified |
| `sandbox-exec` profile, proven by paired tests | ✅ 7/7 on device |
| `posix_spawn` wiring | ✅ value layer + service side wired |
| Flip the switch that lets it execute | ✅ flipped 2026-08-20 — 🔒 first real execution not yet reported |
| UI actions (AX / CGEvent): coordinate mapping, key chords | ✅ value layer + dry run on device |
| Flip the switch that lets it move the pointer | 🔒 not yet |

The capability opened by that switch is deliberately narrow: `shell` actions only,
seven read-only tools from a fixed table (`cat` `ls` `head` `tail` `wc` `grep` `find` —
never the shell itself), writes confined to the sandbox workspace, no network, home
directory closed, secret paths denied separately, and every action still passes local
risk classification and a human confirmation in the HUD. Flipping it back is a one-line
change, by design.

## Getting started

Requires macOS 26+, Xcode 16+, [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```bash
./scripts/bootstrap.sh          # install deps, generate the Xcode project
open apps/CoPartner/CoPartner.xcodeproj
```

Then ⌘R. CoPartner is an `LSUIElement` app — no Dock icon, no window. Look for the eye
icon in the menu bar.

**Run `./scripts/bootstrap.sh` again whenever files are added or removed** — the Xcode
project is generated from `project.yml` and is not checked in.

The Python sidecar and the LiteLLM gateway are **not** needed for day-to-day use: OCR
runs through macOS Vision, and narration runs on-device. The sidecar exists for the
optional vision-language path.

## Verifying the security boundaries yourself

The security properties are not asserted, they are demonstrated. Two scripts do this
without needing Xcode:

```bash
./scripts/sandbox-verify.sh                                   # paired sandbox tests
swiftc -O -o /tmp/xpc-probe scripts/xpc-probe.swift && /tmp/xpc-probe   # deny path
```

`sandbox-verify.sh` is worth reading even if you never run it. It encodes a lesson
that cost several rounds to learn: **testing only that things are blocked produces
false confidence.** Under `deny default` almost nothing can start, so a profile that
blocks *everything* passes every negative test. So each rule is checked in both
directions — the forbidden thing must fail under the sandbox *and* succeed without it,
and the permitted thing must still succeed under the sandbox. If the positive baseline
fails, every negative result is reported as **inconclusive** rather than as a pass.

## How this project is built

Development happens in an agent container with **no Mac, no screen, no permissions**.
All platform glue is therefore written blind and can only be validated by dogfooding:

```
write glue (+ CI-testable tests) → CI green → pull, bootstrap, ⌘R
  → report from the real machine → fix → mark milestone ✅
```

Two principles fall out of that constraint and run through the whole codebase:

- **Injectable backends, honest placeholders.** Platform-heavy work sits behind a
  protocol so CI can test the logic with a fake. Unwired backends `throw` — they never
  silently pretend to have succeeded. A placeholder that reports success turns every
  later verification into a check of a fiction.
- **Safety invariants encoded in types, not comments.** `ApprovalToken` has an
  `internal` initializer, so bypassing the confirmation gate is not expressible outside
  its module. `ProposedAction` has no "shell command string" field at all — only
  `argv: [String]` — so there is nothing to inject into.

See [`docs/design/sandbox-threat-model.md`](docs/design/sandbox-threat-model.md) for the
threat model (T1–T10) and the testable invariants (I1–I10) they map to.

## Privacy

Local-first; sensitive data does not leave the machine. See
[`docs/privacy/data-classification.md`](docs/privacy/data-classification.md). Personal
data belonging to the Shanghai team is subject to China's PIPL cross-border rules and
is hard-blocked from egress; the Taiwan side is subject to PDPA.
