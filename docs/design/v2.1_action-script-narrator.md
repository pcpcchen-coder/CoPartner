# V2.1 補充設計 — Action Script Narrator(操作行為連續敘事子系統)

> **定位**:本文件是 V2 的**增量設計(design delta)**,不是重寫。新增一個常駐子系統:本地快速模型持續把使用者操作寫成 human-readable 的 **action script**(操作劇本)並滾動彙總;熱鍵觸發時,把這份劇本(而非/優先於截圖)交棒給雲端大模型,由大模型「接手續寫」。
>
> **它改寫了 V2 的哪幾節**:`D 本地模型餵圖策略`(新增敘事三段)、`C 觀察緩衝與記憶`(劇本成為記憶主幹)、`E 雲端整合`(ContextEnvelope 改以劇本為主)、`F 觸發與介入流程`(交棒語意)。其餘 V2 章節(擷取引擎 B、隱私 G、沙箱 H、路線圖 J)沿用,僅在對應處標注插入點。

## TL;DR

- **三層劇本**:L0 事件日誌(deterministic 模板,**零模型成本**,捕捉每一個動作)→ L1 敘事步驟(本地 LLM 每數秒/活動邊界 rollup,加意圖推測)→ L2 段落摘要(切 app/每幾分鐘,進長期記憶)。**95% 事件不碰模型**。
- **模型選擇**:L1/L2 主用 Apple **FoundationModels** 3B(`@Generable` 結構化輸出、`prewarm()`、on-device 免費),fallback Qwen2.5-3B-MLX;L0 純規則模板無模型。
- **交棒(handoff)**:熱鍵→打包「滾動劇本(文字)+ 當前焦點小圖 + focused element AX + 剪貼簿」送雲端。文字劇本比連續截圖便宜 ~100×、可 prompt-cache、可稽核。雲端拿到的是**因果歷史 + 未完成的 open loop**,直接續寫,使用者免重新解釋。
- **持續監控不爆算力**:event-boundary 觸發(非定頻)、idle 自動暫停、backpressure 批次化。L0 永遠完整,L1 只在有意義時觸發。

## 1. 子系統在 V2 架構中的位置

```
[Smart Capture Engine (V2-B)]  [CGEventTap]  [AXObserver]  [NSPasteboard]
        │ 結構化事件(焦點app/window, AX role+value, dirty-tile OCR delta,
        │              鍵鼠/scroll/clipboard, tile語意標籤 typing/reading/video)
        ▼
┌─────────────────────────────────────────────────────────────┐
│            [NEW] Action Script Narrator                       │
│  ┌──────────────┐   ┌────────────────┐   ┌────────────────┐  │
│  │ L0 EventLog  │──▶│ L1 Narrator    │──▶│ L2 Summarizer  │  │
│  │ 模板, 無模型 │   │ FoundationMdl  │   │ FoundationMdl  │  │
│  │ append-only  │   │ 3B, 每5-15s    │   │ 3B, 切app/數分 │  │
│  └──────────────┘   └────────────────┘   └────────────────┘  │
│         │ 滾動視窗(RAM, 最近5-15min 熱劇本)                   │
└─────────┼────────────────────────────────────────────────────┘
          ├──▶ L1/L2 寫入 [記憶系統 V2-C] (sqlite-vec, 劇本=檢索主幹)
          └──▶ 熱鍵時 [ContextEnvelope V2-E] 以劇本為主體交棒 → Claude
```

劇本子系統夾在 **觀察/記憶服務** 與 **推理層** 之間:吃擷取引擎的結構化事件(**不吃原始像素**),產出記憶主幹與交棒文字。

## 2. 三層劇本資料結構

### L0 — 事件日誌(deterministic,無模型)

append-only,每個顯著事件一行,純模板生成。捕捉**全部**動作(完整性保證),成本趨近零。

```
[14:30:02.110] FOCUS   app=Xcode win="EMSController.swift"
[14:30:05.400] TYPE    field=AXTextArea text="func reconnectWebSocket() {"
[14:30:11.880] PASTE   chars=58 preview="WebSocket disconnect code 1006…"
[14:30:18.020] SWITCH  app=Safari win="urlsession websocket retry backoff - Google"
[14:30:33.500] SCROLL  app=Safari dir=down dist=1840
[14:30:41.200] FOCUS   app=Xcode win="EMSController.swift"
```

事件分級(只有「顯著」事件成行,連續打字合併、滑鼠移動不記只更新 attention):

| 事件 | 是否成行 | 合併規則 |
|---|---|---|
| app/window 切換 | 是 | — |
| focused element 變更 | 是 | — |
| 文字輸入 | 是 | 同欄位 2s 內合併成一句 |
| 貼上/剪下/複製 | 是 | preview 截斷 + PII 遮罩 |
| 點擊有 AX label 的控件 | 是 | — |
| scroll | 節流 | 1s 視窗聚合方向+距離 |
| 滑鼠移動 | 否 | 只更新 attention heatmap(V2-C.4) |
| DYNAMIC tile(影片) | 是(一次) | 標 `WATCH video`,不逐幀記 |

### L1 — 敘事步驟(本地 LLM,週期性)

每 **5–15 秒** 或 **活動邊界**(app 切換、長停頓、貼上大段、焦點視窗變更)觸發一次,把累積的 L0 壓成一個帶意圖的 step。結構化輸出(便於記憶檢索與交棒打包):

```swift
import FoundationModels

@Generable struct ActionStep {
  @Guide(description:"ISO8601 起始時間") var startedAt: String
  @Guide(description:"主要 app bundle 名") var app: String
  @Guide(description:"動作類別: editing/reading/searching/debugging/configuring/communicating/watching")
  var category: String
  @Guide(description:"一句話客觀描述使用者做了什麼,繁中") var whatHappened: String
  @Guide(description:"推測的使用者目標,繁中;不確定就說不確定") var inferredGoal: String
  @Guide(description:"0-1 信心度") var confidence: Double
  @Guide(description:"涉及的關鍵物件: 檔名/URL/錯誤碼等") var artifacts: [String]
  @Guide(description:"是否為未完成的進行中動作") var openLoop: Bool
}
```

```swift
actor NarratorL1 {
  private let session = LanguageModelSession(instructions: """
    你是螢幕操作敘事器。輸入是一段時間內的低階事件日誌,
    輸出一個 ActionStep:客觀描述 + 謹慎的意圖推測。
    禁止臆測事件日誌沒有的資訊。只輸出結構化結果。
    """)
  func warmUp() async { try? await session.prewarm() }   // 降冷啟動延遲

  func narrate(_ l0lines: [String]) async -> ActionStep? {
    guard case .available = SystemLanguageModel.default.availability else {
      return RuleBasedNarrator.fallback(l0lines)   // 不可用→規則式或 Qwen
    }
    let prompt = "事件日誌:\n" + l0lines.joined(separator: "\n")
    return try? await session.respond(to: prompt, generating: ActionStep.self).content
  }
}
```

L1 範例輸出(對應上面 L0):
> `{category:"debugging", whatHappened:"在 EMSController.swift 撰寫 reconnectWebSocket 並貼入一段斷線日誌(code 1006),接著到 Safari 搜尋 exponential backoff 重試做法", inferredGoal:"為 WebSocket 斷線實作指數退避重連", confidence:0.82, artifacts:["EMSController.swift","WebSocket 1006","exponential backoff"], openLoop:true}`

### L2 — 段落摘要(本地 LLM,粗粒度)

切 app session / 每幾分鐘,把多個 L1 step 滾成一段敘事,丟棄細節,寫入 V2-C 的 L3 加密長期記憶。這就是使用者要的「**彙總**」。

---

## 3. 滾動視窗與彙總(對應 V2-C 記憶)

| 層 | 內容 | 保留 | 儲存 |
|---|---|---|---|
| 熱劇本 | L0 原始行 + 最近 L1 steps | 最近 5–15 min | RAM ring buffer |
| 溫劇本 | L1 steps + embedding | 數小時~天 | sqlite-vec(劇本=檢索主幹) |
| 冷劇本 | L2 段落摘要 | 長期 | SQLCipher(V2-C.L3) |

**劇本取代「截圖序列」成為記憶的主要可檢索物**:語意檢索(「上週四我為什麼改那個重連邏輯」)直接打在 L1/L2 文字 embedding 上,比對截圖 OCR 精準且便宜。對應 V2-C.1 的事件聚合,L1 step 就是「app 級語意事件」的具體實作。

## 4. 交棒機制(熱鍵 → 雲端接手)— 改寫 V2-E.1 / F.2

### 4.1 ContextEnvelope(劇本為主體)

```json
{
  "trigger_ts": "2026-05-29T14:31:05+08:00",
  "action_script": {                         // ← 主體,文字,便宜可快取
    "session_summary": "(L2) 過去 12 分鐘在處理 EMS 的 WebSocket 重連…",
    "recent_steps": [ /* 最近 5-8 個 L1 ActionStep,含 openLoop 標記 */ ],
    "open_loop": "正在 EMSController.swift 寫 reconnectWebSocket,尚未完成退避邏輯"
  },
  "focus_snapshot": "data:image/jpeg;base64,…",   // ← 次要,僅焦點小圖做視覺對齊
  "focused_element": {"role":"AXTextArea","selected":"func reconnectWebSocket() {"},
  "clipboard_recent": "WebSocket disconnect code 1006…",
  "attention_summary": "近 10s 注視 Xcode 編輯區與終端機輸出",  // V2-C.4 熱圖轉述
  "takeover_contract": {
    "instruction": "接手完成 open_loop 所述任務;高風險動作需確認",
    "policy": "confirm_each",
    "allowed_tools": ["text_editor","bash(sandboxed)","computer"]
  }
}
```

### 4.2 交棒語意(takeover contract)

雲端模型收到的不只是「歷史」,而是明確的**接手契約**:
1. **狀態**:滾動劇本(因果史)+ open loop(未完成動作)+ 當前焦點視覺對齊。
2. **可假設什麼**:劇本中 `confidence` 高的意圖可直接採信;低信心或 `inferredGoal` 標不確定者,先問使用者一句再動手。
3. **控制權回收**:任一步驟使用者按 ⌃⌥⌘.(V2 kill-switch)→ 立即停手,劇本標記 `handoff_aborted`,本地敘事繼續。
4. **續寫而非重啟**:system prompt 明示「使用者已做到 open_loop 這一步,從這裡接續,不要重做已完成步驟」。

### 4.3 時序(對應 V2-F.2,強調劇本帶來的低延遲/低成本)

```
t0  熱鍵 ⌃⌥⌘Space
t0+5ms   XPC 取熱劇本(RAM,已是現成文字,無需現場 OCR/敘事)
t0+30ms  sqlite-vec 撈相關歷史 L2 摘要(可選)
t0+40ms  FoundationModels 3B 判斷路由 + 是否需出境(PII/上海個資 → local-only)
t0+60ms  打包 ContextEnvelope(劇本文字為主, payload 小)→ LiteLLM
t0+~200ms Claude 首個 chunk(穩定前綴 reference/系統prompt 命中 prompt cache)
t0+~700ms 首個 tool_use → confirm_each UI / sandboxed executor
```

關鍵:**劇本是隨時備好的**(背景持續產生),熱鍵當下不必現照、現 OCR、現敘事,所以打包延遲主要只剩 RAM 讀取。

## 5. 持續監控的算力預算(這是「快速模型」的關鍵)

| 工作 | 頻率 | 模型 | 單次成本 |
|---|---|---|---|
| L0 模板成句 | 每事件(高頻) | **無** | ~微秒 |
| L1 敘事 rollup | 每 5–15s / 活動邊界 | FoundationModels 3B(prewarm) | M4 級 ~150–300ms |
| L2 段落摘要 | 切 app / 每數分鐘 | FoundationModels 3B | ~300–500ms |
| idle 期間 | 無事件 | **暫停,零成本** | 0 |

**控制策略**:
- **event-boundary 觸發,非定頻**:沒有新顯著事件就不喚醒 L1。
- **idle 暫停**:`CGEventTap` 偵測無輸入 N 秒 → 敘事 pause(擷取引擎也進 COLD,V2-B.6)。
- **backpressure 批次化**:快速連打時 L0 照單全收,L1 對該批次只敘事一次(不逐字)。
- **fallback 階梯**:FoundationModels 不可用 → Qwen2.5-3B-MLX → 純規則模板(L0 直接當劇本,降級但不中斷)。

> FoundationModels 為 ~3B on-device,適合此類「結構化短輸出 + 意圖分類」,**不適合**長推理/factual;必做 `availability` 檢查與 fallback。Qwen3 / 更新小模型若於 mlx-community 釋出更快 checkpoint 可平替。

## 6. 隱私與稽核(對應 V2-G,劇本是優勢不是負擔)

- **全本地產生**:L0/L1/L2 皆在 on-device 模型完成,劇本不主動出境。
- **出境前洗 PII**:交棒打包時,劇本走 V2-G.1 的 tile 遮罩 + Presidio。敏感欄位在 **L0 階段就遮罩**:`[在密碼欄輸入]`、`[貼上疑似卡號,已遮罩]`,連本地劇本都不留明文。
- **透明可稽核**:劇本是 human-readable,「到底送了什麼給雲端」一行行看得到 → 比送一堆截圖更可審查。稽核日誌(V2-G.3)直接附上交棒當下的劇本快照 + `context_hash`。
- **熱圖隱私沿用 V2-C.4**:attention 只進劇本的 `attention_summary` 自然語言轉述,不送原始座標時序。

## 7. 對路線圖的插入點(對應 V2-J)

| 既有 milestone | 插入 |
|---|---|
| **M2 局部 OCR + AX 文字** 後 | 新增 **M2.5 — L0 EventLog**:deterministic 模板成句,純文字劇本無模型,驗收「劇本完整重現一段操作」 |
| **M4 本地推理** 內 | 併入 **L1/L2 敘事器**(FoundationModels @Generable + prewarm + fallback),驗收 L1 意圖推測主觀準確率 + 單次延遲 < 300ms |
| **M5 雲端 + 動作** 內 | ContextEnvelope 改以劇本為主體 + takeover contract;驗收「不貼任何說明,熱鍵後 Claude 能正確接續 open loop」 |

L0(M2.5)可獨立先做且立即有用(等於一個本地操作日誌/時間機器),是低風險高回報的起點。

## 8. 與 V2 既有設計的關係小結

- **餵圖策略(V2-D)**:本地模型的角色從「看圖」擴張為「看圖 + 寫劇本」;Qwen2.5-VL 仍只在需要視覺語意時對焦點拼接圖跑,日常敘事由更輕的 FoundationModels 3B 吃結構化事件文字。
- **記憶(V2-C)**:劇本(L1/L2)成為 sqlite-vec 的主要 embedding 來源,截圖/tile 退為輔助佐證。
- **雲端(V2-E)**:image-heavy → text-first。reference frame 仍走 prompt cache,但**主上下文是劇本**,token 大降。
- **觸發(V2-F)**:因劇本常駐備好,熱鍵延遲主要剩 RAM 讀取與雲端往返。

> **一句話**:V2 讓 AI「看得省」(foveated capture),V2.1 讓 AI「記得清、交棒快」(action script)。前者管像素,後者管語意與時間線。
