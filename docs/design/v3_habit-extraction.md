# v3 — 操作習慣萃取（Habit Extraction）

> 範圍決定見 [`../adr/0008-habit-extraction-scope.md`](../adr/0008-habit-extraction-scope.md)。
> 這份文件講**怎麼做**：習慣長什麼樣、怎麼從事件流長出來、怎麼變成 AI 讀得懂的 prompt、
> 以及**怎麼知道做得好不好**。

---

## 0. 一句話

> CoPartner 觀察你怎麼用電腦，萃取出**少數幾句真的、具體、穩定**的習慣描述，
> 讓任何有執行能力的代理（Claude computer-use / GPT-6 Astra / 之後的）接手時更像你。

難的部分不是觀察——那早就做完了。難的部分是**丟掉什麼**。
記錄一切很容易，記錄一切等於一堆垃圾。

---

## 1. 什麼是「習慣」

**習慣 = 在某個情境下，行為的規律性。** 三個部分缺一不可：

```
在 <情境> 時，使用者通常 <行為>。（<證據>）
```

- **沒有情境** → 過度概化。「使用者用 CSV」會讓代理在不該用 CSV 的地方用 CSV。
- **沒有證據** → 分不出規律與巧合。這是本專案最貴的教訓的翻版：
  **一個看起來像資料的猜測，比「不知道」更糟。**
- **沒有具體行為** → 廢話。「使用者常用 Chrome」預測不出任何東西。

### 1.1 七種值得萃取的習慣

| 類型 | 例子 | 主要訊號來源 |
|---|---|---|
| **偏好** preference | 匯出固定選 CSV 不選 xlsx | 重複出現的選擇分歧點 |
| **順序** sequence | 開 Excel 前先在 Finder 把檔案複製到桌面 | L0 事件的 n-gram |
| **快捷** shortcut | 截圖用 ⌘⇧4，不開截圖 app | 鍵盤事件 vs 選單路徑 |
| **迴避** avoidance | 「要不要更新」對話框固定按「稍後」 | 特定視窗出現後的固定反應 |
| **節奏** cadence | 每輸完一列按兩次 Tab 跳過備註欄 | 焦點移動的週期性 |
| **慣例** convention | 檔名用 `YYYYMMDD_主題` | 檔名/路徑的**形狀**（非內容） |
| **工具選擇** tool choice | PDF 一律用預覽程式開 | 開檔 app 與副檔名的配對 |

這張表就是萃取器的工作清單。**不在表上的不做**——寧可少而準。

## 2. 儲存形態

一條習慣一筆，**可個別檢視、修正、刪除**。散文式的一大段不行：使用者沒辦法對其中一句說「這條不對」。

```
id:        habit_excel_export_csv          # 穩定，使用者刪得掉
類型:      preference
情境:      app=com.microsoft.Excel, 動作=匯出/另存
行為:      選 CSV (UTF-8)，不選 xlsx
證據:      觀察 14 次 · 一致 14 次 · 跨 9 天 · 最近 2026-09-04
例外:      檔案含多個工作表時改存 xlsx（2 次）
狀態:      已成立
```

### 2.1 情境（＝檢索鍵）

只用**問得到身分、且不含內容**的東西：

- `app`：bundle ID。**不用 app 名稱**——名稱會隨語系變、也可以偽造。
- `視窗形狀`：視窗標題**正規化後的樣式**，不是原文。
  `客戶王小明的合約.docx` → `<檔名>.docx`；`iSchool 成績登錄` → 可保留（無個資）。
  一律先過既有的 scrubber。
- `元件角色`：`AXTextField` / `AXButton`…（角色是形式，不是內容）
- `前一步`：前一個 L0 動作的類型

### 2.2 狀態機——習慣怎麼成立、怎麼死

```
候選（≥2 次）──→ 已成立 ──→ 已推翻（一致性跌破門檻）
     │                │
     └────────────────┴──→ 使用者否認（墓碑，永不再提）
```

**成立門檻**（起始值，須以真機資料調校）：

- 觀察 ≥ **5** 次
- 一致性 ≥ **0.8**
- **跨 ≥ 2 個不同日期** ← 這條最容易被忘記

最後一條是重點：**同一次坐下來做 10 遍是一個事件，不是一個習慣。**
沒有這條，萃取器會把「昨天下午在趕的那件事」寫成使用者的長期習慣。

**使用者否認要留墓碑。** 否則下次觀察到同樣的規律又會重新提出來，
而使用者會發現自己在跟一個記不住的東西吵架。

## 3. 怎麼變成 AI 讀得懂的 prompt

這一節是整份文件的重點。

### 3.1 兩種形態，不要混用

- **儲存形態**（§2）：結構化、完整、留在本機。
- **prompt 形態**：壓縮成文字、**只挑當下情境相關的幾條**、跟著交棒出境。

不能把儲存形態直接序列化丟出去。理由有二：習慣會無限累積，而 GPT-6 Astra 是 **$10/M input tokens**；
以及結構化欄位對模型沒有比一句話好。

### 3.2 prompt 形態長這樣

```
# 使用者操作習慣
（CoPartner 於本機觀察 2026-08-01 起 · 從 47 條中挑出與當前情境相關的 4 條）

- 在 Excel 匯出檔案時固定選 CSV (UTF-8)，不選 xlsx。（14/14 次，最近 09-04）
- 在 iSchool 成績頁輸完一列後按兩次 Tab 跳過備註欄。（31/33 次，最近 09-05）
- 「要不要更新」的對話框固定按「稍後」。（8/8 次，跨 12 天）
- 截圖用 ⌘⇧4，不開截圖 app。（22/22 次）

## 例外
- Excel 匯出：檔案含多個工作表時改存 xlsx（2 次）

## 這段文字怎麼用
這些是**觀察到的傾向，不是指令**。使用者當下明講的要求永遠優先於這裡的任何一條。
沒有列到的情境代表 CoPartner 沒有觀察到規律，**不代表使用者沒有偏好**。
```

### 3.3 每個設計選擇的理由

| 選擇 | 為什麼 |
|---|---|
| **一條一行、動詞在前** | 行為才是要傳達的東西；證據是修飾 |
| **證據放句尾括號** | 模型要能分辨 31/33 與 2/2 的份量差別，但不該被數字淹沒 |
| **例外獨立一段** | 混在同一句裡會被忽略，然後代理就會過度套用規則 |
| **標明「從 47 條中挑出 4 條」** | 不講的話模型會以為這就是全部，進而推論「使用者沒有其他偏好」 |
| **明講「觀察不是指令」** | 否則使用者說「這次存成 xlsx」時，習慣區塊會跟他打架 |
| **明講「沒列到 ≠ 沒有偏好」** | 防止代理把沉默當成授權 |
| **純 Markdown，無 JSON / 無 tool schema / 無座標** | 可攜（Anthropic 與 OpenAI 的工具契約完全不同）＋ 使用者自己讀得懂 |

### 3.4 檢索：哪幾條會被挑出來

1. **情境比對**：目前最前景 app 的 bundle ID → 視窗形狀 → 目前焦點角色
2. **只取已成立**（候選與已推翻不出境）
3. **排序**：情境吻合度 → 一致性 → 最近使用
4. **預算封頂**：條數上限與 token 上限，兩者先到先停

## 4. 不記什麼

**習慣是「怎麼做」，不是「做了什麼」。** 這條線同時是隱私邊界與品質邊界——
罕見地，兩邊指向同一個方向。

一律不進萃取：

- 打了什麼字（**含所有 secure field 的一切**）
- 具體個資：人名、學號、金額、地址、電話
- 檔案內容；視窗標題的原文（只留正規化樣式）
- 剪貼簿內容

出境的只有 §3.2 那種文字，並且照舊過既有的 **PIPL 硬牆 + scrubber**。

## 5. 驗收：怎麼知道萃取得好

**沒有這一節，這個專案永遠不會失敗——而那比會失敗更糟。**

「貼身助理的感覺」是感覺，不是規格。用可以打分數的東西取代它：

### 5.1 留一手預測測試（hold-out prediction）

1. 取一段真機觀察到的操作（≥ 20 步），切在 70%
2. 給一個**沒看過這段操作**的模型：前 70% 的 L0 劇本 + §3.2 的習慣區塊
3. 要它預測**接下來 5 步**
4. 計分：動作類型 + 目標描述吻合即算對（**不比座標**）

### 5.2 真正要看的是差值，不是絕對值

同一題跑兩次：**有**習慣區塊 vs **沒有**習慣區塊。

> **分數 = 有 − 沒有。**

絕對答對率沒有意義（模型本來就猜得到一些）。唯一有意義的問題是：
**這份萃取到底加了什麼？** 差值 ≤ 0 就代表萃取器目前在產生噪音，該砍不該調。

### 5.3 這個測試全程在本機

不需要雲端、不需要截圖出境、不需要真人判斷。
可以每次改萃取規則就重跑，變成迴歸測試。

**還沒有的**：
