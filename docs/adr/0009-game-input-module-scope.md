# 9. GameInput：獨立自用的遊戲輸入模擬模組（不是 CoPartner 的一部分）

- 狀態：已接受（2026-09-13）

## 脈絡

需求是「模擬鍵盤滑鼠操作 Roblox」。這件事跟兩天前才通過的 ADR-0008
（**CoPartner 是操作習慣的萃取，不是執行器**）表面上直接衝突——
0008 明列 `UIActionPerformer` / `UIActionGate` / `KeyChord` / `VirtualKeyMap`
「`main` 上移除」，而遊戲輸入需要的正是同一組能力。

所以第一件要做的事不是寫程式，是把 0008 的三條論據逐條拿來檢查，
看它們對「遊戲輸入」到底成不成立。結論是**三條都不成立**，但理由各自不同：

### 1.「操作能力正在商品化，自建執行層是永遠落後的第三名」

不成立，因為商品化的不是同一種能力。`computer_20251124` 與 GPT-6 Astra 做的是
**桌面 app 的離散動作**：截圖 → 算座標 → 點一下。它們的 tool schema 裡
**沒有任何一個 primitive 表達得出「按住 W 一點二秒」**——而遊戲輸入的本質就是
時間軸上的連續狀態，不是離散事件。

`ProposedAction.Kind` 自己就是這件事的證據：`.click(x, y)`、`.keypress(raw)`
——每一個都是「按一下就結束」，型別上組不出「按住」。這不是實作沒跟上，
是那套抽象服務的是另一個問題域。

這一格沒有「落後第三名」的問題，因為沒有人在跑這條賽道。

### 2.「自建執行層要獨力承擔全部執行安全責任」

不成立，因為那份責任來自**模型自己決定要點哪裡**。0008 擔心的形狀是
「一次點擊就可能按到『刪除』，而 UI 這一側沒有沙箱兜底」——危險的是決策，
不是送事件這個動作本身。

`GameInput` 不含決策（見下方硬約束 2）。它收一份已經寫明白的 `InputPlan` 並執行，
最壞情況是**按住的鍵沒放開**——嚴重、但形狀完全不同：它是一個有明確技術解的
不變式問題（帳本 + `releaseAll`），不是一個開放的信任問題。

### 3.「沒有可靠的內容偵測器」

不成立，因為那是**截圖出境**的問題。0008 的死結是「送圖出去之前擋不住裡面的祕密」。
`GameInput` 不送任何東西出境（硬約束 3），這個死結在這裡不存在。

順帶一提：0008 的第 1 點親口寫下「**遊戲**同理」——遊戲在 AX 上是不透明節點。
那句話當時是拿來論證偵測器不可靠的，但它對本模組是另一個意思：
**現有 `UIActionPerformer.dryRun` 的核心驗證手段（AX 報出「那個位置上是什麼」）
對 Roblox 會回「讀不到」。** 驗證方式必須重新設計，見實作文件的驗證階梯。

## 決定

**`GameInput` 是一個獨立的自用工具模組，不是 CoPartner 這個產品的一部分。**

ADR-0008 原封不動，執行層照計畫從 `main` 移除。`GameInput` 與那層**沒有任何相依**，
所以移除 PR 不會碰到它，它也不會把已經死掉的東西拖著不放。

### 四條硬約束

1. **不依賴 `ActionExecutor`。** 那個 target 會消失，任何相依都等於預約一次
   「移除主線時順手弄壞 GameInput」。`VirtualKeyMap` 的鍵碼表**刻意複製一份**
   進 `GameInput`——重複是有意識付的代價，換到的是這個模組可以獨立生、獨立死。
   （複製時同樣用 Carbon 具名常數，理由與原版相同：寫死數字打錯不是「按不到」，
   是「按到別的鍵」。）

2. **不含決策。** `GameInput` 只執行明確寫出來的 `InputPlan`。
   「什麼時候該按什麼」由呼叫端決定，模型不在這個模組裡。
   這條約束是第 2 點論據能成立的前提——一旦讓模型直接驅動它，
   0008 對執行安全的擔憂就原封不動地回來了，那時候要重開一份 ADR，不是默默加功能。

3. **不出境。** 不送截圖、不呼叫雲端、不含任何網路程式碼。

4. **不進 CoPartner 主管線。** 擷取／敘事／記憶／習慣萃取那條線**不得** import
   `GameInput`。app target 可以有一個獨立的選單入口，但那是共用外殼，不是共用管線。

## 後果

**新增**：`packages/CoPartnerKit/Sources/GameInput/`（新 target，只相依 Foundation／CoreGraphics／Carbon）。

**不變**：ADR-0008 的範圍決定、習慣萃取的路線、執行層與截圖出境層的移除計畫。

**風險（接受）**：

- **Roblox 使用條款禁止 bot／macro／automation，帳號可能被停權。**
  這是產品外部的事實，不是技術可以解掉的，記在這裡讓之後讀到的人不必重新發現。
- **`.cghidEventTap` 不保證進得去遊戲。** 遊戲若走 IOHID raw input 路徑，
  合成事件可能被完全忽略——這是整個模組的**核心未知**，
  實作計畫因此把它排成第一個要證偽的東西，而不是最後才發現。
- **沒有 ground truth 靶場。** 開發直接對正式遊戲進行（使用者決定），
  所以「沒反應」無法從遊戲內部確認原因。緩解方式是三層驗證階梯，
  把單一的「沒反應」切成三種可區分的失敗——但那是推論，不是證明。
