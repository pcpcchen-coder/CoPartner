# 8. 範圍重畫：CoPartner 是操作習慣的萃取，不是執行器（habit extraction, not execution）

- 狀態：已接受（2026-09-05）

## 脈絡

M5 走到最後一哩時卡在「送截圖」這一步，而卡住的方式很有教育意義：

1. **焦點式敏感偵測在瀏覽器上失效。** 真機兩次乾跑證明 Chromium 的無障礙樹是懶啟動的，
   整個網頁在 AX 上是一個不透明節點，裡面的密碼欄不會以 `AXSecureTextField` 出現。
   Electron（VS Code / Slack / Discord）、Java、遊戲、自繪 UI 同理。
2. **改成 AX 全樹掃描不會變好。** 覆蓋率依然看 app 臉色，而且**失敗模式沒變**——
   「找不到祕密就整張送出去」。從像素找（OCR 找那排圓點）是同一個病的另一種實作。
3. **結論：沒有可靠的內容偵測器。** 防線只能改用可靠訊號（app 身分白名單），
   而那又跟「無縫接手」「接手會跨視窗」直接衝突（見對話紀錄）。

在解這個死結的過程中，一個更上游的問題浮出來：**CoPartner 為什麼要自己執行？**

同一週，兩家旗艦模型都把 computer use 做成主打能力：

- Anthropic `computer_20251124`（截圖 → 座標）
- OpenAI **GPT-6 Astra**（2026-09-03 發表、09-05 公開）：computer use 走截圖 + 背景控制，
  OSWorld 2.0 從 GPT-5.6 的 65.7% → **72.6%**，每任務約 75 分鐘 → 約 40 分鐘。

操作能力正在商品化。CoPartner 自建執行層的終局是「永遠落後的第三名」，
而且要獨力承擔全部的執行安全責任。

反過來看，**雲端廠商拿不到的是「這個人平常怎麼用他的電腦」**——那需要長期在本機看著，
而且是一人一份，他們的規模優勢在這裡沒有用武之地。OpenAI 自己的說法也把這一格畫在模型外面：
檔案、記憶、檢索索引、憑證、工具權限、日誌**都存在 context window 之外**。

## 決定

**CoPartner 的產品是「使用者操作習慣的萃取」，不是執行器，也不是自動化的安全層。**

- **做**：長期觀察 → 萃取操作習慣 → 產出**人類可讀、廠商中立的文字**，
  交給任何有執行能力的代理（Claude computer-use / GPT-6 Astra / 之後的東西）使用。
- **不做**：不執行 UI 動作、不送截圖出境、不承擔自動接手的執行安全責任。
  那些屬於接手的那一端。

推論出的四條硬約束（細節見 `docs/design/v3_habit-extraction.md`）：

1. **輸出是純文字，不綁任何 API。** 不含座標、不含 tool schema、不含 JSON 結構。
   可攜性（要同時餵得動 Anthropic 與 OpenAI）與可驗證性（使用者自己要讀得懂）指向同一件事。
2. **一句話一個習慣，且必須帶證據**（觀察次數 / 一致性 / 最近時間）。
   看過兩次的不是習慣。沒有次數，模型分不出規律與巧合——那就回到本專案最貴的教訓：
   **一個看起來像資料的猜測，比「不知道」更糟**。
3. **必須可按情境檢索，不能整包塞。** 習慣會無限累積，而 Astra 是 $10/M input tokens。
   進 prompt 的永遠是「與當下情境相關的那幾條」。
4. **只記形式，不記內容。** 習慣是「怎麼做」不是「做了什麼」。
   打了什麼字、什麼金額、什麼人名一律不進萃取——這條線同時是隱私邊界與品質邊界。

## 後果

**出局（程式碼仍在 git 歷史中，`main` 上移除）**：

- 執行層（step 53.5–53.6）：`ExecutorService`、`XPCActionPerformer`、`UIActionPerformer`、
  `UIActionGate`、`TakeoverPolicyGuard`、`ScreenCoordinateMapper`、`KeyChord`、`VirtualKeyMap`
- 截圖出境層（step 55–61）：`ScreenshotEgressPolicy`、`ScreenshotEncoder`、
  `ScreenshotRedaction`、`ScreenshotScalePolicy`、`SensitiveTileMask`、`SensitiveMaskEvidence`
- M6 的「密碼欄 100% 被遮」驗收條件：不再適用（不送圖就沒有這個問題）

**留下且升格為核心**：擷取引擎、L0 事件劇本、焦點/視窗追蹤、記憶系統、
文字出境硬牆（PIPL 閘門 + scrubber）——出境的只剩文字，這層剛好是對的形狀。

**風險**：廠商也會做記憶。差異在 CoPartner 看的是**整台電腦**而不是與單一助理的對話，
但這不是永久護城河。接受。

**驗收條件改變**：「熱鍵後 Claude 正確接續 open loop」不再是 M5 的驗收。
改為可打分數的預測測試——把觀察切兩半，前半 + 習慣萃取交給**沒看過這段操作**的模型，
讓它預測後半；答對率即萃取品質。全程本機可跑，不需雲端、不需出境、不需真人判斷。
沒有這個，萃取層永遠不會失敗，而那比會失敗更糟。
