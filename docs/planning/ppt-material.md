## Slide 5 — 看得省：向人眼與 VNC 借的兩個點子

**版面**：螢幕示意圖——中間紅框（高解析高頻）、外圍灰階（低解析低頻）、右下角影片區打叉

- **中央窩成像（foveation）**：滑鼠／焦點區高解析高頻，周邊低解析低頻——人眼就是這樣運作的。
- **增量更新（dirty-region）**：借鏡 KVM-over-IP／VNC，只處理「變動的 tile」。
- **雙訊號交叉驗證**：`SCStream.dirtyRects` 當主訊號、**Metal per-tile dHash** 當 ground truth——不信任單一來源。
- **冷熱狀態機**：COLD／WARM／HOT／**DYNAMIC**；影片區自動標 DYNAMIC 並**跳過 OCR**。

> 📊 實測：擷取 idle CPU **9%**、operating **25%**（系統整體僅 ~10%）。

**講稿**：「定頻全螢幕截圖 + 全螢幕 OCR 在 24GB 的 M4 上長時間跑，光影片區就燙手。所以第一個決定就是：**不要全部看**。」

## Slide 6 — 記得清：為什麼是「劇本」不是截圖

> 圖：`04a-dataflow-本地感知鏈`

```
L0  14:07:12  [切到 Safari]
    14:07:31  [複製 “func reconnect(attempt:)” 附近 12 行]
    14:11:02  [切回 Xcode · WebSocketClient.swift]
L1  「使用者正在為 WebSocket 重連加入指數退避，
      已查到參考實作，尚未套用」  ← 本地 3B 產出
L2  「14:00–14:15 debug WebSocket 重連」
```

- **截圖是單一瞬間，劇本是因果史**——交棒要的是後者（ADR-0004）。
- 三層滾動彙總：L0 模板（零模型、完全確定性）→ L1 FoundationModels 3B → L2 段落摘要。
- **階梯會回報自己用了哪一層**——關掉 Apple Intelligence 就掉回規則式，不中斷。

> 📊 實測：L1 敘事延遲 **1373–2388ms**（本地 3B，逐 token 串行生成）。

**講稿**：「你要它接手，它需要知道的不是『畫面長什麼樣』，是『你為什麼走到這一步』。」

## Slide 7 — 交棒快：四道閘

> 圖：`04b-dataflow-出境與雲端` + `04c-dataflow-風險閘與執行`（上下兩條流程帶）

```
劇本 + 焦點小圖
   → ① EgressGate 出境閘門（PIPL 命中 → 整包拒出，只走本地）
   → ② LiteLLM Gateway（預算熔斷）
   → Claude computer-use → ComputerUseNormalizer → ProposedAction
   → ③ 風險分級（high 一律人按）→ 接手 HUD：Approve / Skip / Stop
   → ApprovalToken（不過線）→ XPC service（雙向 code-signing 驗證）
   → ④ sandbox-exec sbpl + posix_spawn argv 直呼（無 shell）
   → 稽核四態 → UndoStack
```

**講稿**：「四道閘任何一道都能單獨擋下來。而且注意最後一段——動作是在**另一個程序**裡、在**沙箱**裡、用 **argv 直呼**執行的，全程沒有一個 shell。」

## Slide 10 — 方法論：沒有 Mac 怎麼寫 macOS app？

**這是全場最有記憶點的一頁**——開發代理跑在 Linux 容器，沒有 Mac、沒有 GPU、沒有螢幕、沒有權限。

| 原則 | 做法 |
|---|---|
| **可注入後端** | 平台重活（Metal／SCK／vec0／FoundationModels／computer-use／XPC）全藏在 protocol 後，CI 用假後端驗邏輯 |
| **誠實佔位** | 沒接線的真後端一律 `throw .notWired`，**絕不靜默假成功** |
| **兩種完成定義** | ✅ CI 驗證完成（我可自主判定）／🔒 需要真機驗證（要你回報） |
| **build 綠 ≠ 真的編到了** | `canImport` 為 false 時整檔靜默略過、build 照樣綠 → `#if`／`#else` 兩側各放 `#warning` 取得**編譯期證據** |

**結果**：91% 的工作在**沒有真機**的情況下被驗證過。

**講稿**：「這不是巧思，是被逼出來的。但逼出來的結果是——每一個平台依賴都變成一個明確的注入點，我永遠知道『哪裡還沒接真的』。」

## Slide 11 — 安全：把不變式寫進型別系統

> 圖：`05-security-安全隱私邊界`

| 設計 | 效果 |
|---|---|
| `ApprovalToken` 的 `init` 是 **`internal`** | 只有同模組的 HUD 狀態機能鑄造 → **「繞過確認閘門的呼叫路徑」在編譯層面不存在** |
| `ApprovalToken` **不過 XPC 線** | 跨程序的值可以偽造，所以授權留在偽造不了的地方（主 app 內驗） |
| `ProposedAction` **沒有整串 shell 欄位**，只有 `argv: [String]` | 型別層面消滅 metacharacter 注入面，executor 不經 `sh -c` |
| **沒有驗證就不可以有執行能力** | XPC service 先做成沒有執行能力的骨架，驗簽補上後才翻開開關 |
| 模型輸出 = **不可信提議** | 每個動作過「與模型推理無關的本地規則」+ 人工確認，防線不依賴 prompt |

**講稿**：「間接 prompt injection 的防線不能是『我在 prompt 裡叫它不要聽壞人的話』。螢幕上出現的任何指令都是不可信的，所以防線必須在**模型之外**。」

## Slide 12 — 翻開執行能力那天，能力範圍刻意極窄

**版面**：一張「允許 vs 拒絕」對照

翻開 `willExecuteActions = true` 之後，CoPartner **能做的事**：

| 允許 | 拒絕 |
|---|---|
| 只有 `shell` 一種動作 | 檔案動作明確拒絕 |
| 只有固定表裡**七個唯讀工具**：`cat`／`ls`／`head`／`tail`／`wc`／`grep`／`find` | **永遠不含 shell 本身** |
| 只能寫沙箱工作目錄 | 家目錄關閉、秘密路徑另外 deny |
| — | 網路全斷 |
| 每個動作仍需本地風險分級 + HUD 人工確認 | 高風險任何政策都必須人按 |

**兩個工程決定值得講**：

1. **翻開的那一行單獨成立一個 PR。** 理由：翻開執行能力若混在一大包程式碼裡，沒有人（包括作者）能真的審完。
2. **第一次真執行用本地合成提議**，走**完全相同**的路徑（風險分級 → HUD → token → 全部閘門 → XPC → sbpl）。它不繞過任何閘門，只是把提議來源從雲端換成本地——讓第一次真執行發生在完全受控的情況下，而不是在第一次接上雲端時。
3. **驗收判定是「stdout 裡有那串隨機標記」，不是 `didExecute == true`**——沙箱擋掉讀取時 `cat` 照樣會結束、`didExecute` 照樣為真，stdout 卻是空的。

**講稿**：「翻回 `false` 是出事時的第一個動作，只要改一行。這件事本身就是設計的一部分。」

## Slide 13 — 隱私：縱深五層

| 層 | 機制 | 狀態 |
|---|---|---|
| 1 文字層 | `PIIMasker` — 卡號／身分證／密碼欄在寫進劇本**之前**就遮 | ✅ 真機驗過 |
| 2 tile 層 | `SensitiveTileMask` — 敏感區不 OCR、不持久化 | 🔒 待 M6 |
| 3 來源層 | `SCContentFilter` 黑名單 — 黑名單 app **0 frame** 進來 | 🔒 待 M6 |
| 4 聚合層 | 注意力熱圖只存**聚合權重**，不存內容 | ✅ |
| 5 出境層 | `EgressGate` — PIPL 命中**整包拒出**，只准走本地階 | 🔒 待 M5 收尾 |

**法遵**：台灣 PDPA + 上海團隊的中國 PIPL 跨境條款。敏感命中時**強制 local-only，不 fallback 雲端**。

**還有一個刻意的「不做」**：UI 執行端**不支援截圖**。截圖是給模型看的，該由擷取管線產生並經出境閘門（PII 遮罩 + PIPL）。在執行端偷截一張＝靜默拿掉整個出境設計。

## Slide 14 — 只有真機會現形的五個 bug（很受歡迎的一頁）

1. **FOCUS 狂刷** — 終端機每輸出一個字就被判定換視窗，同一秒噴十幾行。
   *根因*：焦點追蹤誤用 AX `value`（欄位**內容**）當視窗識別。後來又抓到同源的另外三類：會變的標題／「讀不到」／兩個不同來源的欄位當身分。四條回歸測試釘住。
   **教訓：邏輯正確、測試也過——錯在真機餵給它的資料。**
2. **OCR 截整螢幕** — 混入選單列和其他 app 文字，吞吐等同沒優化。*修*：依 AX 焦點框裁切 → **18%**。
3. **Vision bbox 左下原點** — 與螢幕座標慣例相反，沿用會讓摘要**上下顛倒**。
4. **稽核不誠實** — 被閘門擋下的動作原本留下**零痕跡**；執行未成功時原本記成已執行。*修*：改成 `attempt`／`executed`／`notExecuted`／`blocked` 四態。
5. **sbpl 路徑陷阱** — 給 `/tmp/x` 的規則對 `/private/tmp/x` **永遠不匹配**，而 profile 看起來完全正常。*修*：先 `realpath`；順帶補上路徑跳脫（安全設定裡的注入面）。

**講稿**：「這五個沒有一個是 CI 抓得到的。第一個尤其可怕——所有測試都是綠的，因為測試餵的是乾淨資料。」

## Slide 15 — 一場七輪的記憶體診斷（方法論最強的一頁）

**版面**：一條記憶體曲線，前段陡、後段平

**症狀**：**沒開觀察**、只是讓 app 開著就會跳系統記憶體告警。

這一句話就排除了原本兩個主要嫌疑（`CaptureEngine` 無上限 `AsyncStream`、每 3 秒全螢幕截圖）——兩者都只在觀察開始後才存在。

**診斷過程本身推翻了我自己的三個中途結論：**

| 中途結論 | 為什麼是錯的 |
|---|---|
| 「持續成長」 | 一次性暖機被**整體斜率**攤成了成長率 |
| 「還是在成長」 | **階段落差**被攤成了成長率（斜率不該跨越狀態邊界）|
| 「ratchet 確認：停止後不回落」 | **量測時機**造成的假象——停止後 1–5 分鐘記憶體根本還沒開始掉，真正的落定點在 30 分鐘 |

**真正的成因**：`AsyncStream<TileEvent>` 沒指定 buffering policy（無上限），而它唯一的消費者是一個 `@MainActor` 計數器——每個事件都要跳一次 MainActor，產生端不會等它。同一條管線上游的 `SCKFrameProducer` 早就用了 `.bufferingNewest(2)`。

**結果**：改成 `.bufferingNewest(64)` → **+151 MB/小時 降到 +7 MB/小時**，並出現修正前完全沒有的 8 分鐘完全持平區段。

**一句話總結**：**一個看起來像資料的猜測，比「不知道」更糟。**

> 附帶設計：**刻意不用定時器取樣**。要量的正是閒置路徑，在上面裝一個定時醒來的東西等於在被觀察的對象裡加一個新的觀察者。改成每次打開選單取一個樣，背景成本恰好是零。

## Slide 16 — 「驗證方式比被驗的東西重要」

**版面**：兩欄——錯的驗法 vs 對的驗法

沙箱 profile 怎麼驗？

| 錯的 | 對的 |
|---|---|
| 只測「擋得住」 | **成對驗證**：正向基準 + 負向結果 |
| deny-default 下什麼都跑不起來 → 全綠 | 負向結果**依賴**正向基準；基準沒過時全部標「**無效**」而非「通過」 |
| 得到一個永遠會通過的測試 | `./scripts/sandbox-verify.sh` → 7 項全綠、0 失敗、**0 無效** |

**講稿**：「一個測不出東西的測試，比沒有測試更危險——因為它會讓你以為你驗過了。」

**同一個原則的另一個例子**：`canImport` 隔離的程式碼，build 綠不代表編到了。用 `#if`／`#else` 兩側各放一個 `#warning`，看到黃字才算數。

## Slide 17 — 一個「算術上不可達」的目標

原訂 L1 敘事目標 **~300ms**。實測 2659ms，壓到 1373ms 後**到頭了**。

> 端上 3B 逐 token 串行生成，延遲幾乎與**輸出長度**成正比。
> 300ms 的預算只夠 12–15 個 token——塞不下 6 欄位結構化輸出裡的兩段散文加一個陣列。
> **這是輸出形狀與模型吞吐的算術，不是調校問題。**
> 再壓要砍 `inferredGoal` 欄位，代價是失去 L1 的全部價值。→ 目標依實測修訂為 **~2.5s**。

**附帶發現**：`@Guide` 的字數上限模型**只當參考、不嚴格遵守**（設 20 字、實測輸出 35 字）——所以延遲會在 1373–2388ms 間浮動。

**講稿**：「這頁想講的是**怎麼對待一個訂錯的目標**。不是硬調參數調到天亮，是算一次數學，然後帶著理由去改目標。」

## Slide 19 — 誠實的風險與已知缺陷（強烈建議保留這頁）

| 項目 | 現況 |
|---|---|
| **L1 會編故事** | 終端機標題 `CoPartner — -zsh — 100×34` 被 3B 腦補成「與 CoPartner 進行**視訊會議**」。指令已明寫禁止臆測，3B 壓不住。這是 L1 品質調校，與 M5 是兩條線 |
| **XPC 不是權限降級** | 原本假設 service 跑在低權 user——**做不到**，內嵌 XPC service 必然與主 app 同 uid（實測 euid 501）。買到的是**程序隔離**，真正的圍籬來自 sbpl。記為殘餘風險 R5 |
| 真 `vec0` 磁碟量未驗 | step 36 專門跑 8 小時驗（目標 ≤ 400MB）|
| 擷取 CPU 目前固定 2fps、每幀 hash 全螢幕 tile | step 23.5 優化已排（⏸ 延後，非遺漏）|
| 同 app 內換視窗仍記 FOCUS | 只有 CI 測試蓋到，下次 dogfood 開兩個終端機視窗切一下就能補驗 |
| 全日音訊（V2）的心理與社交成本 | 同意機制 + 訪客模式；一週 dogfood 是隱藏驗收項 |
| iOS 背景錄音限制（V3 最大技術風險）| 先做 spike；備援＝錄音墜飾硬體提前 |
| 單人開發、V2+V3 合計約一年 | 每版都設計成「該版結束即有完整可用產品」，不是半成品接力 |

**講稿**：「我把不確定的東西列出來，不是為了免責，是因為**知道哪裡不確定本身就是進度**。上面第二條尤其重要——那是一個我原本寫在設計文件裡、被真機實測推翻的假設。」

## Slide 20 — 收尾

> 圖：`06-versions-版本階梯`

**三句話**：

1. **它已經會看了**——M0／M2／M2.5／M4 真機通過，app 每天開著用。
2. **它已經會動了**——沙箱執行端建成、開關翻開；剩下的是把提議來源從本地換成雲端。
3. **然後讓它離開電腦**——V2 給耳朵、V3 給手腳、V4 給眼睛。

| 版本 | 一句話 | 跳出電腦 | 時程 |
|---|---|---|---|
| **V1 CoPartner** 🔄 | 桌面 ambient 助理：看螢幕、寫劇本、熱鍵交棒 | 0% | → 2026-12 |
| **V2 Listen** | 全日音訊 → 生活劇本；Telegram 閘道讓你在任何地方對話 | 30% | 2027-01 → 05 |
| **V3 Agent** | 技能引擎、heartbeat 主動巡檢、手機／手錶衛星 | 70% | 2027-06 → 11 |
| **V4 Omni** | 穿戴優先：眼鏡、墜飾、即時耳語協助 | 100% | 2028+ |

**貫穿架構：Hub-and-Satellites** — Mac mini M4 永遠是中樞，手機手錶眼鏡都是衛星（感測器 + 介面，不存資料、不做重推理）。**這讓「本地優先、敏感不出境」的承諾在每一版都成立。**

**最後一句**：「這個專案真正在賭的是一件事——**AI 助理的瓶頸不是模型有多聰明，是它知不知道你在幹嘛。**」

## 附錄 D — Q&A 預備

| 可能被問 | 怎麼答 |

| 「一直錄螢幕不會很耗電？」 | 這正是「看得省」要解的。實測 idle 9%。核心是不全看：foveation + dirty-region + 影片區跳 OCR。 |

| 「螢幕上有惡意指令怎麼辦？」 | 威脅 T1 間接注入。防線在模型之外：模型輸出一律當**不可信提議**，過與模型推理無關的本地規則 + 人工確認。 |
